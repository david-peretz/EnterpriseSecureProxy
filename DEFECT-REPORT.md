# Defect Report

## Scope

The assessment does not supply a baseline repository, so this report covers the defects that were **discovered and fixed
in this solution itself**: first while the test suite was being built against the implementation, then during an
independent review pass over the finished code. Every row uses the table format requested by the assessment (file,
observed behaviour, root cause, risk, fix, test), and every fix is pinned by an automated test in
`tests/SecureProxy.Tests` so that it cannot regress silently.

* **Section A** – defects discovered and fixed.
* **Section B** – defect classes that the design prevents by construction. They did not occur in this solution; they are
  the review checklist that was applied to it, and that applies to any proxy of this kind.
* **Section C** – the method used.

## A. Defects discovered and fixed

| File / component | Observed behaviour | Root cause | Risk or impact | Fix | Test |
| --- | --- | --- | --- | --- | --- |
| `Proxy/EnvelopeReader.cs` | The "exactly one of `json` / `encryptedJson`" check was written as `json is null == encrypted is null` and was not evaluated as the intended comparison | Operator precedence in a pattern-matching expression; no parentheses | An envelope carrying both payload members, or neither, could pass envelope validation and continue with an ambiguous payload | Explicit `(json is null) == (encrypted is null)`; both-present and none-present → `400 envelope.invalid` | `RejectionTests.Envelope_must_contain_exactly_one_payload_member` |
| `Proxy/DestinationCircuitBreaker.cs` | After the break period a single half-open probe was admitted, but if the probing caller cancelled, hit the concurrency limit or was stopped by the audit policy, the probe slot was never cleared | Probe state was reset only on an upstream success or failure; other exit paths did not report back | Circuit latched open for that destination until process restart – a self-inflicted outage | Probe held as a lease: `TryEnter` / `RecordSuccess` / `RecordFailure` / `Release`, released on every exit path of the executor (`finally`), plus expiry of an unreported probe after the break period | `ResilienceTests.Probe_abandoned_by_a_cancelling_caller_does_not_latch_the_circuit_open`, `Unit.SecurityUnitTests.Released_or_lost_probe_never_latches_the_circuit_open` |
| `Proxy/OperationCatalog.cs` | A configuration lookup that started before `Invalidate(key)` could write the *old* configuration into the cache after the invalidation | Load-then-set without checking whether an invalidation happened in between | A disabled operation or destination could keep being forwarded for a full cache TTL although the admin change was acknowledged | Per-key epoch and a global generation are captured before the database load; the result is cached only if both are unchanged (`ResolveAsync`); `InvalidateAll()` bumps the generation that is part of the cache key | `AdminConcurrencyTests.Disabling_an_operation_takes_effect_immediately_and_is_recorded_in_history`, `Requests_already_executing_complete_with_the_configuration_they_started_with` |
| `Proxy/ParameterValidator.cs` | Pattern rules were evaluated with `Regex.IsMatch(value, pattern)`, which accepts a match anywhere in the value | Unanchored regular expression; no match timeout | Validation bypass – a value such as `123abc` or `..%2F` satisfied a `[0-9]+` rule; pathological patterns could stall a thread (ReDoS) | Every pattern is wrapped as `^(?:pattern)$` regardless of how it was configured; 100 ms match timeout, timeout → invalid (fail closed) | `Unit.ParameterValidatorTests.Pattern_is_anchored_so_partial_matches_do_not_pass` |
| `Proxy/ParameterValidator.cs` | A path parameter rule configured as optional allowed the value to be omitted | `IsRequired` applied uniformly to all locations, but a path placeholder cannot be left empty | Request reaches URL construction with an unbound placeholder → configuration error (500) instead of a caller fault, or an unintended URL | Path parameters are required regardless of the configured flag; missing value → `400 parameters.invalid` | `Unit.ParameterValidatorTests.Path_parameters_are_required_even_when_configured_as_optional` |
| `Proxy/HeaderPolicy.cs` (response) | Upstream responses were relayed byte-for-byte while `Content-Encoding` was dropped by the response allow-list | The always-relay list contained only `Content-Type` | Compressed upstream bodies became undecodable for callers (a `gzip` body without the header) | `Content-Encoding` travels with the body: always relayed together with `Content-Type` | `Unit.HeaderPolicyTests.Response_headers_follow_default_and_operation_allow_lists_but_never_leak_internals` |
| `Proxy/EnvelopeReader.cs`, `Security/AesGcmPayloadDecryptor.cs` | `encryptedJson.keyVersion` was optional; a payload without a version was decrypted with whatever key the profile currently referenced | Convenience default | After a key rotation, old ciphertexts and ciphertexts of unknown provenance were indistinguishable; rotation could not be enforced | `keyVersion` is mandatory and must equal the profile's `KeyVersion`; missing → malformed payload (`400`), mismatch → `KeyVersionMismatch` (`400`), never forwarded | `EncryptionTests.Wrong_key_version_is_rejected`, `EncryptionTests.Malformed_encrypted_payloads_are_rejected` |
| `Security/ISecretSource.cs` | `ConfigurationSecretSource` kept resolved key material in a process-lifetime cache | Premature optimisation | A rotated secret behind the same reference was not picked up without a restart; decoded key bytes stayed in memory indefinitely | Secrets are resolved on every call from `IConfiguration` (which already reloads); no cache, decoded bytes are short-lived | `Unit.SecurityUnitTests.Resolves_only_well_formed_references` |
| `Proxy/EnvelopeReader.cs` → `RequestLogs.ReasonDetail` | The rejection reason stored in the audit row for unknown envelope members was the public error message, which lists the member names supplied by the caller | One text used for both the response and the audit record | Caller-controlled text persisted in the audit table (log injection, accidental personal data at rest) | `ProxyRejection.AuditDetail`: the response keeps the helpful message, the audit row stores a fixed description | `AuditPolicyTests.Audit_records_never_contain_headers_bodies_or_secrets`, `RejectionTests.Rejected_request_is_audited_as_rejected_and_not_forwarded` |
| `Program.cs` (admin rate limiting) | `/api/admin/*` was protected by the API key only; unlimited attempts were possible | Rate limiting applied to the proxy endpoint only | Online brute force of the admin key | Dedicated `Admin` rate-limit policy, partitioned per client address (`Resilience:AdminRateLimitPermitPerMinute`), same `429` problem response | `AdminConcurrencyTests.Admin_endpoints_require_the_api_key` (filter); limiter shared with `ResilienceTests.Requests_beyond_the_per_client_limit_are_rejected_with_429_and_not_forwarded` |
| `Admin/ConfigurationAdminService.cs` | An operation's HTTP method could be changed to a body-less method while body parameter rules existed, and a path template could be changed so that its placeholders no longer matched the path parameter rules | Field-level validation only; no cross-field consistency check | A valid-looking admin change that makes every subsequent request fail (or build an unintended URL) | Method changes are checked against the body rules, template changes against the path rules and `UpstreamUriBuilder`; rejected with `400` and the concurrency stamp is not bumped | `AdminConcurrencyTests.Invalid_configuration_changes_are_rejected` |
| `Proxy/ProxyExecutor.cs` | A caller that disconnected mid-request surfaced as an unhandled `OperationCanceledException`: audited as `ProxyError` (500), logged as an error, and the attempt to write a response to the closed connection threw again | Cancellation treated like any other exception | Misleading audit and error logs (false alarms on every client disconnect); noisy exceptions | `OperationCanceledException` with `RequestAborted` set → outcome `CallerCancelled` (499) recorded in the single audit point; writes to a closed connection are tolerated | `ReliabilityTests.Caller_cancellation_is_propagated_to_the_upstream_and_distinguished_from_a_timeout` |
| `src/SecureProxy.Api/appsettings.Development.json` | Development key material was committed with the source, and the documented demo value did not decode to the 32 bytes AES-256 requires | Convenience during development | Key material in version control; every encrypted demo call failed with `400` (fail closed, but unusable) | No key material anywhere in the repository; keys come from user-secrets / environment (`openssl rand -base64 32`), the decryptor enforces exactly 32 bytes (`KeyUnavailable` otherwise) | `Unit.SecurityUnitTests.Classifies_failures_without_ever_returning_plaintext` (wrong key length → `KeyUnavailable`) |

## B. Defect classes prevented by design

| File / component | Defect class | Root cause | Risk or impact | Prevention as implemented | Test |
| --- | --- | --- | --- | --- | --- |
| `Proxy/EnvelopeReader.cs` | Envelope members such as `url`, `destinationUrl`, `method`, `path` accepted and used (or silently ignored) | Request DTO bound with a permissive deserializer; routing data read from the request instead of configuration | Caller chooses the upstream → full SSRF / open proxy | Strict envelope: known members only, any unknown member → `400 envelope.unknown_member`; routing comes exclusively from `Operations`/`Destinations` | `RejectionTests.Caller_supplied_routing_information_cannot_override_configuration` |
| `Proxy/ProxyExecutor.cs` (step 6) | `urlId` used to look up / build the destination URL | Treating a caller value as routing input | Caller redirects traffic to another configured or arbitrary destination | `urlId` is only compared with the configured destination key; mismatch → `400`; never used to build a URL | `RejectionTests.UrlId_that_does_not_match_the_configured_destination_is_rejected`, `Missing_urlId_is_rejected` |
| `Proxy/UpstreamUriBuilder.cs` | Path parameters concatenated into the URL without encoding/validation; `../`, `%2F`, `?`, `#` accepted | String concatenation instead of segment-aware construction and post-build validation | Path traversal to admin endpoints, query injection, host escape | Whole-segment placeholders, conservative value allow-list (no `/ \ % ? #`, no `..`), `Uri.EscapeDataString`, final URL re-validated against base URL (scheme/host/port/path prefix/dot segments) | `RejectionTests.Path_traversal_attempts_are_rejected` (10 cases), `Unit.UpstreamUriBuilderTests` |
| `Proxy/ProxyExecutor.cs` (steps 2-4) | Disabled operations / destinations still forwarded; lookup ignores `IsEnabled` | Missing checks or `Where` clause only on key | Decommissioned or blocked APIs remain reachable through the proxy | Explicit enabled checks for operation **and** destination before any other processing; method allow-list applied even to configured values | `RejectionTests.Disabled_operation_is_rejected_and_not_forwarded`, `Disabled_destination_is_rejected_and_not_forwarded`, `Operation_configured_with_a_disallowed_http_method_is_rejected_as_invalid_configuration` |

| `Proxy/HeaderPolicy.cs` (response) | Upstream `Set-Cookie`, `Server`, `Location` relayed to callers | Response headers copied wholesale | Session fixation across tenants, internal host disclosure | Response allow-list (default + per operation) and never-relay list | `ForwardingTests.Upstream_response_headers_are_relayed_only_when_allow_listed` |

## C. Method

1. **Read first, change nothing.** Trace `POST /api/proxy/execute` end to end and list every place where request data
   influences destination, method, path, headers or audit.
2. **Reproduce each suspected defect with a failing test** using the `RecordingHandler` mock destination
   (`tests/SecureProxy.Tests/Infrastructure`). The assertion must include "the destination received nothing" for anything
   that should have been rejected.
3. **Fix the root cause**, not the symptom (e.g. anchor every pattern centrally instead of fixing one configured rule).
4. **Keep the test** so the defect cannot come back, and record the row in the table above.
